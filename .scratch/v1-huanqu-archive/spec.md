# Spec: 唤取档案 V1 —— 纯本地鸣潮唤取记录统计助手

Status: ready-for-agent
Date: 2026-09-26
来源：定稿原型 `docs/prototype/index.html` + PRD V1.0 + ADR-0001..0007 + 技术调研（docs/research-2026-09-25-gacha-api.md）。术语一律遵循 CONTEXT.md。

## Problem Statement

鸣潮 PC 玩家想知道自己的运气到底怎么样：保底垫了多少抽、歪没歪、平均多少抽出金。但游戏内的唤取记录只是一份流水列表——没有任何统计；官方只保留约 6 个月的记录，更早的抽卡历史会永久丢失；社区的网页工具要么要把个人数据交给在线服务处理，要么要自己跑脚本导出。而获取数据本身有技术门槛：唤取链接只能从客户端本地日志里提取，新版日志还有 XOR 混淆，官方接口没有公开文档。

玩家需要一个装上就能用、数据不出本机的 Windows 桌面工具：一键把唤取记录拉到本地永久保存，然后直截了当地告诉他——你这个人，到底是欧是非。

## Solution

「唤取档案」（工作名）：Tauri 2 Windows 桌面应用。

- **获取**：只要玩家在游戏内打开过唤取记录页，点一下「一键同步」即可自动定位游戏目录、从日志提取唤取链接、按卡池拉取全量历史，本地合并去重后永久保存；手动粘贴唤取链接作兜底。
- **展示**：单画面「五星编年史名册」——时间倒序的五星卡片网格，每张卡片一眼可读三件事：结局（UP/歪）、程度（超欧/超非）、属性；配评语行（评级字母 + 趣味评语）、右栏保底引线（距必得还差几抽）与高光时刻纪念牌。
- **管理**：记录抽屉看全量流水，设置弹窗管主题、自动同步、目录探测、JSON 备份恢复与清空数据。
- **隐私**：除向官方接口拉取玩家自己的记录外零网络请求，全部统计与存储在本地完成。

## User Stories

### 获取与数据

1. 作为鸣潮 PC 玩家，我想在游戏内打开过唤取记录页之后点一下「一键同步」就自动完成全部导入，so that 我不需要看教程或跑脚本。
2. 作为玩家，我想让软件自动探测游戏安装目录（注册表 / MuiCache / 防火墙规则 / Xbox / 常见路径扫描），so that 我不用手动找日志文件在哪。
3. 作为玩家，当自动探测失败时，我想手动指定安装目录并被记住，so that 任何非常规安装位置也能用。
4. 作为玩家，我想让软件同时读取 Client.log 与 KRSDK debug.log 两处日志，so that 任意一处有可用链接都能成功。
5. 作为玩家，当日志是新版 XOR 混淆格式时，我想软件自动解码（先原文匹配、失败再解码），so that 新旧版本客户端都能支持。
6. 作为玩家，当游戏正在运行时，我也想能读取日志（共享读），so that 不用先退出游戏。
7. 作为国服玩家，我想软件识别国服链接并请求国服接口；作为国际服玩家亦然，so that 两个服的玩家都能用。
8. 作为玩家，我想在同步时看到「正在获取 卡池 x/13」的进度，so that 我知道软件在干活而不是卡死了。
9. 作为玩家，当找不到目录 / 日志里没有链接（没打开过唤取页）/ 日志被 Engine.ini 关闭 / 日志只读 ACL 时，我想看到对应的具体诊断和下一步指引，so that 我能自己解决问题而不是只看到「失败」。
10. 作为玩家，当唤取链接过期（code != 0）时，我想被明确告知并引导「重新打开游戏内唤取记录页后重试」，so that 我不会把它当成网络故障反复重试。
11. 作为不愿折腾的玩家，我想直接粘贴唤取链接完成导入（与一键获取同一管线），so that 一键失败时我仍有路可走。
12. 作为多号玩家，当日志里检测出多个 UID 时，我想看到列表并选择要导入的档案，so that 不会导错号。
13. 作为换号玩家，当检测到与当前档案不同的 UID 时，我想收到切换确认（旧档案只读保留），so that 两个号的记录互不污染。
14. 作为玩家，我想每次同步只增量并入新记录（time+name+qualityLevel+池 code 去重），so that 重复同步不产生重复数据。
15. 作为老玩家，我想官方 6 个月窗口之外的历史记录永久保留在本地且只增不减，so that 我的完整抽卡历史不会随官方过期而消失。
16. 作为刚抽完卡的玩家，我想看到「新记录约 30 分钟后可同步」的提示，so that 我不会把查不到新记录当成 bug。
17. 作为在意数据安全的玩家，我想导出全部记录为 JSON 并能导入恢复（按同一去重键合并、往返一致），so that 换机重装不丢数据。
18. 作为玩家，我想用「清空数据」删掉当前档案（二次确认），so that 我能从头开始。
19. 作为玩家，我想写库是事务化的，so that 同步中途崩溃不会留下半写状态。
20. 作为断网环境的玩家，我想除「获取」外统计、浏览、备份全部可用，so that 网络状况不影响日常使用。
21. 作为注重隐私的玩家，我想在界面上随时能看到「所有数据仅保存在本机」的声明，so that 我放心。

### 编年史主画面

22. 作为玩家，我想打开应用就看到本池的评语行（评级菱章字母 + 评语 + 平均出货 + 歪率），so that 三秒内知道自己是欧是非。
23. 作为玩家，我想以时间倒序浏览全部五星的卡片网格名册（最新在前），so that 抽卡历程像一本档案。
24. 作为玩家，我想每张卡片显示头像（缺图回退属性色菱形 + 名字首字字牌）、名字、属性/武器类型、出货抽数大数字 + 0–80 微条、歪/UP 徽章和日期，so that 一眼读全。
25. 作为玩家，我想 UP 卡用强调色温洗底 + 顶边 + 实心徽章、歪卡用冷灰并压暗角色名，so that 扫一眼就能数出几个 UP 几个歪。
26. 作为玩家，我想出货数字与微条按程度着色（≤20 绿、≥70 红、其余中性），so that 极端欧非自动跳出来。
27. 作为玩家，我想名册头部有汇总芯片（UP n · 歪 n · 超欧 n · 超非 n），so that 不用逐卡数。
28. 作为玩家，我想名册首位有虚线「进行中」卡显示当前垫抽数与距必得剩余，so that 我知道这一抽走到哪了。
29. 作为玩家，我想点击/键盘选中卡片后，下方详情条展示该五星完整信息，so that 想细看时不用弹窗打断。
30. 作为玩家，我想在四类池页签（角色精准调谐 / 武器精准调谐 / 常驻调谐 / 新手·感恩）间切换，同一类别多个卡池时在页签内二级切换，so that 每个池的账各是各的。
31. 作为玩家，我想顶部一行汇总指标（总唤取、五星数、平均出货、歪率）随页签联动，so that 每个池的规模心中有数。
32. 作为玩家，我想名册在 50+ 个五星时依然换行流畅、内部滚动，so that 长线玩家不受阻。
33. 作为玩家，常驻池出货抽数超过 80 时微条按实际长度显示、重复五星标「重复」章，so that 常驻池的规则差异被如实呈现。
34. 作为新手期玩家，我想新手·感恩池不计入欧非总评（评级「—」、评语「启程之人」），so that 规则特殊的新手池不污染我的评价。
35. 作为玩家，抽到未知卡池 code 的记录时，我想它落入「未知池」兜底页签做浅统计，so that 官方加新池不会让软件崩坏。

### 保底与高光

36. 作为玩家，我想在右栏看到三条保底引线（角色精准 / 武器精准 / 角色常驻）：已垫 N · 还差 M 抽 + 0–80 刻度，so that 距必得永远可见。
37. 作为角色池玩家，我想引线上标注当前处于小保底还是大保底（上个五星歪了 → 下个必 UP），so that 我决定要不要现在抽。
38. 作为武器池玩家，我想看到「没有 50/50，出货即 UP」的说明，so that 两类池的规则差异不会困惑我。
39. 作为玩家，我想看到高光时刻纪念牌：旅途总览（总抽数/五星数）、最欧（出手如电）、最非（漫长等待）、大保底就绪状态，so that 极端时刻被纪念。

### 记录抽屉与设置

40. 作为玩家，我想从顶栏呼出右侧抽屉浏览全量流水（时间、池、物品、稀有度着色），so that 不离开主画面就能查账。
41. 作为玩家，我想按稀有度芯片与卡池下拉筛选流水（空结果时给「清除筛选」），so that 能快速定位。
42. 作为大数据库玩家，我想流水虚拟滚动在 2 万条时依然流畅，so that 数据量不拖垮体验。
43. 作为玩家，我想在设置里切换明暗主题（明色默认），so that 白天黑夜都舒服。
44. 作为玩家，我想开关「启动时自动同步」（默认开，仅链接有效时静默增量），so that 日常更新零操作。
45. 作为玩家，我想在设置里重新探测 / 查看当前安装目录，so that 换了安装位置能自愈。
46. 作为键盘与读屏用户，我想浮层（抽屉/弹窗）支持焦点往返、ESC 关闭、名册卡片可达且焦点可见，so that 不用鼠标也能完整操作。
47. 作为开了「减少动态效果」的玩家，我想所有动画自动关闭，so that 界面不晃眼。

## Implementation Decisions

**架构与技术栈**

- Tauri 2 桌面壳 + TypeScript 前端，Rust 面最小化（ADR-0001）：Rust 侧仅承担安装目录探测、日志读取（共享读 + XOR 双路径）、带自定义 Referer 的官方 HTTP 请求、SQLite 装配。
- 前端 Vue 3 + TypeScript + Pinia，**无图表库**：编年史名册、微型进度条与保底刻度均为 CSS 实现（ADR-0007）；ECharts 不进入 V1 依赖。
- 业务逻辑（拉取编排、限速重试、合并去重、统计口径、评语）全部在前端 TS 领域模块中，通过端口注入官方 API、存储与时钟，保持可测。
- 发布形态：NSIS 安装包（≤15MB）+ 便携版 zip，V1 无自动更新；仅 Windows 10/11 x64。

**获取管线**（事实依据：技术调研汇报）

- 目录探测优先级：注册表 Uninstall 项 → MuiCache → 防火墙规则 → Xbox `.GamingRoot` → 常见路径扫描（官方启动器 / WeGame / Steam / Epic）→ 手动指定（记住选择）。
- 日志两处：`Client.log`（首选；「先原文匹配、失败再按奇字节 ^0xA5 / 偶字节 ^0xEF 解码」双路径；共享读）与 KRSDK WebView `debug.log`；社区通用正则取最新一条唤取 URL，解析 9 个参数，按 host 或 svr_area 判国服/国际服。
- 拉取：对卡池 code（1..=13 开放式枚举）逐池串行 POST `gacha/record/query`，相邻请求间隔默认 1s（下限 600ms）、单请求超时 15s、失败重试 3 次；**无分页**，每池一次拿全量（时间倒序）；`code != 0` 一律判定链接失效并进入引导，不当作网络错误重试。
- 合并：去重键 `time + name + qualityLevel + cardPoolType`，只增不删，事务化写库；档案以 `player_id` 为键，多 UID 建映射由用户选择。
- 禁止按 API 返回的中文池名做字符串匹配；未知 code 走兜底参数并落「未知池」。

**统计口径与评语**（全量定义见 PRD §5）

- 出货抽数含出货那抽，按池内时间正序计算；池内最早记录即五星时按 1 计并标「不完整」。歪判定采用常驻名单反向判定（ADR-0002），名单为随应用分发的数据文件，未知物品标「未知」不计入歪率；歪率仅对角色系限定池（1/8/10/12）计算，武器系限定池（2/9/11/13）必中 UP。
- 保底：五星硬保底 80（新手调谐池 5 为 50）、四星 10；大小保底状态 = 上一个角色系限定池五星是否歪。
- 评语档位与评级字母（原型 `tierOf` 定稿，角色系限定池五星平均出货）：

| 评级 | 平均出货 | 评语 |
|---|---|---|
| S | ≤ 35 | 天选之人 |
| A | ≤ 50 | 欧洲常驻居民 |
| B+ | ≤ 62 | 手气不错 |
| B | ≤ 70 | 中规中矩 |
| C | ≤ 78 | 玄不救非 |
| D | > 78 | 保底战神 |

  修正项：歪率 ≥80% 追加「命运的反面宠儿」；出过 ≤10 抽五星追加「十里坡剑圣」式彩蛋；角色系限定池五星 <2 个显示「样本不足，多抽点再来」；新手·感恩池评级「—」、评语「启程之人」。
- 程度阈值：超欧 ≤20 抽（绿）、超非 ≥70 抽（红）。期望参考线：角色系 62 抽（社区口径标注），武器系 V1 不显示。

**信息架构与视觉**

- 单画面编年史 + 抽屉/弹窗（ADR-0003）；池页签为四固定类别，类别内多 code 二级切换，未知池动态兜底页签（PRD §9 A8）。
- 五星编年史名册卡片网格为编年史终稿形态（ADR-0007，取代共鸣曲线）；头像/武器图标来自 ryanbenson/wuthering-waves-assets 开源仓库，构建期打包、`resourceId → 文件名` 映射加载，缺图回退字牌（ADR-0005）。
- 视觉遵循设计系统 v11：游戏原生母语（斜切/菱形/黑条），强调色随主题（明 = 共鸣青、暗 = 低饱和金），金贯穿两主题承担五星/评级/荣誉小面积强调（ADR-0004、ADR-0006）；明色为默认主题。
- 状态栏常驻：30 分钟延迟提示、6 个月窗口说明、本地隐私声明、版本号。

## Testing Decisions

好测试只断言模块的外部行为，不断言实现细节。全新代码库无既有先例，测试先行围绕以下接缝（seam）展开：

1. **领域核心接缝（主接缝，数量最少、层级最高）**：前端 TS 领域模块以纯函数 + 端口注入暴露（官方 API 端口、存储端口、时钟）。在此接缝测试：合并去重幂等与只增不减、链接失效判定（code != 0）、限速间隔与重试次数、出货抽数/歪率/保底进度/大小保底状态的计算、评语档位边界（35/50/62/70/78）与程度阈值（20/70）、「不完整」首五星口径、常驻名单未知物品处理。以上全部通过伪造端口驱动，不发真实网络请求。
2. **日志提取接缝**：Rust 提取模块（目录探测 + 共享读 + XOR 双路径 + URL 正则与参数解析）以 fixture 日志文件驱动单元测试——明文旧版、XOR 混淆、多 UID、无 URL、损坏文件等样本。
3. **UI 组件薄层**：以种子数据驱动名册/详情条/抽屉筛选/设置弹窗的渲染与交互（卡片选中、ESC、焦点往返），框架随 Vue 选型（Vitest + Vue Test Utils）；只测用户可见行为。
4. **真机验收**保持人工，走 PRD DoD：国服 + 国际服真实账号一键获取、抓包验证仅官方域名、1 万/2 万条性能、备份往返一致。

## Out of Scope

- V1 不做：分享图、按版本/时间统计、卡池日历、多档案并行展示 UI、浏览旧档案的 UI、自动更新、多语言、四星深度分析、软保底精确概率积分（期望参考线仅用常量）。
- 永不做：云同步或任何形式的数据上传、代抽/自动化外挂功能、macOS 版。
- 依赖层面：任何图表库。

## Further Notes

- 定稿原型 `docs/prototype/index.html` 是交互与视觉的最终基准；实现与原型冲突时，先怀疑实现。
- 运行时探测项（调研 §6）：record_id 实际有效期（不写死时长）、日志混淆算法未来变化（「3.4 加密」传闻未确认）、池 7 是否仍返回数据、`time` 字段时区语义（V1 按字符串原样排序）、WeGame 安装前缀、云鸣潮 URL 双份参数（hash 优先）。
- 官方 6 个月窗口 + 30 分钟延迟是产品事实：状态栏提示与「刚抽完查不到是预期行为」须进入实现。
- 池页签归属（A8）与武器系不显示参考线（A7）是为补全原型未覆盖场景而做的推断决策，若与预期不符请修改 PRD §9 并同步本 spec。
- 测试接缝（尤其「领域核心 + 日志提取」两条自动化接缝的划分）为本次 to-spec 提出的方案，实现前请确认是否符合预期。
