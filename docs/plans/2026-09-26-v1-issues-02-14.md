## 跨任务决策（所有 developer 必须遵守）

### D1 分层与目录（ADR-0001：Rust 面最小化）

- `src/domain/`：纯 TS 领域模块（拉取编排、限速重试、合并去重、统计口径、评语、档案）。**零 Vue/零 Tauri 依赖**，通过端口注入外部世界，全部经伪造端口单测。
- `src/services/`：Tauri 适配层，用 `invoke` 实现 domain 端口（`GachaApiPort` / `StoragePort` / `ClockPort` / `DirProbePort` 等）。
- `src/stores/`：Pinia store，编排 domain + services，持有 UI 状态。
- `src/components/`：Vue 组件（顶栏、评语行、名册、详情条、抽屉、弹窗、状态栏沿用 #01 既有件）。
- `src-tauri/src/`：Rust 仅三块——`gacha.rs`（单次官方 HTTP POST，带 Referer/UA/Content-Type，15s 超时；限速与重试在前端）、`db.rs`（SQLite 装配与读写命令）、`probe/`（#04 目录探测与日志提取；纯函数核心 + `#[cfg(windows)]` 系统调用）。

### D2 数据与存储

- SQLite（rusqlite，`bundled` feature）。库文件位于 Tauri `app_data_dir`（Windows 用户数据目录，与程序目录分离，ADR-0008）。
- 表 `pull_records`：`player_id TEXT, card_pool_type INTEGER, card_pool_id INTEGER, time TEXT, name TEXT, quality_level INTEGER, resource_id TEXT, resource_type TEXT`，唯一索引 `(player_id, time, name, quality_level, card_pool_type)`（= 去重键 + 档案键）。只增不删：`INSERT OR IGNORE`，单事务。
- 注意（research 文档 §2.3）：API 返回里的 `cardPoolType` 字段是**中文池名字符串**，禁止用于匹配；记录落库时的 `card_pool_type`（数字池 code）取「本池请求时已知的 code」。`resource_type`（返回的「角色」/「武器」）入库供统计与名册使用。
- Rust 命令：`db_load_records(player_id) -> Vec<Record>`、`db_insert_records(player_id, records)`（事务化批量）、`db_list_archives() -> Vec<{player_id, count, first_time, last_time}>`、`db_clear_archive(player_id)`。记录 JSON 字段名与官方 API 返回对齐（`cardPoolType/cardPoolId/time/name/qualityLevel/resourceId`，见 research 文档 §返回结构）。
- 合并去重的业务逻辑在前端 `domain/merge.ts` 纯函数（组合键比对，返回仅新增集），DB 的 `INSERT OR IGNORE` 是第二道幂等保险；两层语义必须一致。

### D3 获取管线事实（实现以此为准，全部来自 research 文档）

- URL 参数 9 个：`svr_id/player_id/lang/gacha_id/gacha_type/svr_area/record_id/resources_id/platform`；无签名参数。
- 国服 `POST https://gmserver-api.aki-game2.com/gacha/record/query`；国际服同路径域名为 `.net`。判服：URL host 或 `svr_area`。
- 请求头：`Content-Type: application/json` + 浏览器 UA + `Referer`（国服 `https://aki-gm-resources.aki-game.com/`、国际服 `https://aki-gm-resources-oversea.aki-game.net/`）。
- 请求体 `{playerId, recordId, cardPoolId, cardPoolType, serverId, languageCode}`；无分页，每池一次返回全量（时间倒序）；`code != 0` 即链接失效，不重试。
- 卡池 code 开放式枚举 1..=13（1/2 精准、3/4 常驻、5/6 新手、7 感恩、8/9 新旅、10/11 联动、12/13 忆旅）；未知 code 容错兜底。**禁止**按 API 返回的中文池名做字符串匹配。
- 限速：逐池串行，相邻请求间隔默认 1s（下限 600ms）；单请求超时 15s；网络类失败重试 3 次。时钟/睡眠注入 `ClockPort` 便于假时钟测试。

### D5 测试与回归集

- 前端：Vitest + Vue Test Utils（已配 jsdom），组件测试只断言用户可见行为，种子数据驱动。
- Rust：模块内 `#[cfg(test)]`，fixture 驱动（`src-tauri/src/probe/fixtures/` 下样本日志：明文旧版、XOR 混淆、多 UID、无 URL、损坏）。
- **回归集（本仓库的范围约定）**：`npm test`（全部前端测试）+ `cargo test`（Rust 单测）。当前测试量小、均为快速单测，此即"重要测试"，任何阶段都跑它而不是再筛选；除此之外没有全量套件。类型检查 `npm run typecheck` 与 Rust `cargo check` 属于构建检查。
- 测试范围规定因此解释为：不引入 e2e/真机/网络类测试；单测与组件测试全跑。

### D6 温控与负载（macOS 适配）

- 任何时刻只有一个重负载命令（无并行子智能体、构建与测试不并行）。
- 本机无 pwsh，`run-throttled.ps1` 不可用，替代约定：`vitest run` 加 `--pool=forks --poolOptions.forks.singleFork` 限单线程；`cargo` 命令加 `-j 4`；npm build 不加并发参数（vite/esbuild 自身并发有限）。
- 冷却替代：每个任务收尾后主编 `sleep 60`；测试批次间 `sleep 30`。

### D7 Git 与提交

- 在 `main` 分支工作，不新建分支、不 push。每任务验收通过后主编单独提交一个 commit，信息沿用仓库风格并带编号（如 `feat: 粘贴链接导入端到端 (#02)`）。
- 开工时工作区干净（无用户未提交改动）。
