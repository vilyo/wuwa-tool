# 0006 配色定稿：中性灰阶底座 + 共鸣青界面 + 低饱和金「赢」

原型迭代中收到两份外部配色建议（同一色系的浅/深两种表述：雾白 `#ECEFED`、炭黑 `#171A1C`、深灰 `#292D30`、共鸣青 `#72D5D1`、冷青蓝 `#4FA6AB`、低饱和金 `#C8B783`、深金 `#94845F`）。制作 A/B 临时原型与原暖象牙金版本三方对比后定稿：

1. **底座采用建议方案的中性灰阶与青**：中性灰白/炭黑比原暖象牙更贴近鸣潮真实 UI（冷灰面板 + 青色共鸣科技元素），青色（共鸣青）接管操作按钮、选中态、保底引线、「进行中」波峰等界面/科技语义。
2. **「赢」保留为金色**：建议方案把状态强调给青，但实测青与歪的冷灰同属冷调，削弱了「金/灰 = 赢/歪」的暖冷色温对立（第一层扫读信号）。定稿将 UP 卡底色、UP 徽章、五星名、评级章、荣誉数字划归**低饱和金**（`#C8B783` 系，比此前 `#AE8C3B` 更淡雅）——与建议表自身的用途注释（低饱和金 = 五星、重要元素）一致。
3. 每色一职的最终语义：**金 = 赢（UP/五星/评级/荣誉）→ 灰 = 歪/非高光 → 绿/红 = 欧非程度 → 青 = 界面操作与进行中 → 紫/蓝 = 四星/三星**。
4. 明色（雾白）为默认主题，暗色（炭黑）为夜晚模式；A/B 两个临时原型文件对比完成后删除，仅保留一份原型。

## Considered Options

- 维持暖象牙金（被否）：金色身兼操作/UP/五星三职，语义混用；暖底偏离游戏真实 UI。
- 采纳建议方案原样（部分否）：青色 UP 削弱第一层扫读信号与「赢」的情感表达。

## Consequences

- 设计系统 token 由金主导改为「青（界面）/ 金（赢）/ 绿红（程度）」三系；见 DESIGN-SYSTEM v10。
- 超欧绿与低饱和金、共鸣青的区分度在双主题下均验证通过。
- **补记（同日评审）**：初版定稿把金洗底铺满 UP 卡（.26），浅色主题整体发黄、不如青色 A/B 版清爽——色温在大面积上分裂所致。修正为**面积纪律**：金只做小面积强调（顶边 2px、实心徽章、微条），洗底明色降至 .11、暗色保留 .17（炭黑上的鎏金反而成立）。页面回归冷色统一，赢/歪扫读由顶边 + 实心徽章 + 微洗底共同承担。
- **补记二（终稿，用户拍板）**：最终采用**强调色随主题**——明色主题 = A 版原样（雾白底，共鸣青承担操作/UP/引线/进行中），暗色主题 = 炭黑底、深灰卡、**低饱和金承担全部强调**（不引入青）。低饱和金同时贯穿两主题承担五星/评级/荣誉（小面积）。理由：青天生适合浅色 UI，金天生适合黑底；两主题各自使用其"天生"的强调色，均为 A/B 评审中被接受过的观感。
